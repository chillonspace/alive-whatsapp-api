# 开发日志 / Development Log - 2026-08-02

> 时区 / Timezone: Asia/Kuala_Lumpur

## 今日目标 / Objectives

- 审查 customer-facing Alive Groups endpoint 是否读取 Supabase latest export，以及当前是否可追踪客户拉取次数。
- 为 `GET /alive/groups` 实现对客户透明的 Supabase pull receipts。

## 已完成事项 / Completed Work

- 确认 `GET /alive/groups` 已接入共享 Express app，并使用 `X-API-Key` 保护。
- 确认每次成功认证的请求都会读取 `alive_group_exports` 的 `id = latest` row 并返回 `response` JSON。
- 确认当前 route、全局 middleware 与 schema 都没有 pull receipt、request counter 或 `last_pulled_at` 记录。
- 核对 customer spec DOCX：对外约定为 `GET /alive/groups`，未约定 webhook、ACK 或调用次数追踪。
- 新增 `alive_group_pull_receipts` server-only audit table、index、RLS 与最小 `service_role` privileges。
- 新增 pull receipt service，并在成功读取 latest export 后记录 `consumer_id`、status 与 `exported_at`。
- Receipt insert 使用 best-effort behavior；returned error 或 thrown exception 都不会影响客户 HTTP 200 response。
- Code review 后增加 one-second `AbortSignal` timeout 与 route-level fail-open boundary，避免 tracking hang/rejection 影响客户 response。
- 每次 receipt 使用 application-generated UUID，作为未来 insert-level retry 的稳定 identity；当前 installed PostgREST client 只自动 retry idempotent methods。
- 已将两次 hosted migration 应用到 Supabase `Alive Whatsapp Project`，并完成实际 service-role insert/query verification；verification rows 已清理。

## 技术决定 / Technical Decisions

- 本次仅做只读审查，不修改现有 endpoint 行为或 schema。
- Supabase REST GET logs 只能作为间接线索，不能作为 customer pull count 的可靠业务审计记录。
- Pull receipts 只证明 Alive API 已准备返回 HTTP 200，不证明客户下游已处理 JSON；当前需求不增加 ACK。
- Receipt table 不保存 API key、IP、User-Agent、phones 或完整 response JSON。
