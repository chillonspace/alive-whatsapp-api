## 今日目标 / Objectives

- 调查 production `POST /templates` 返回 `Template create rate limit exceeded` 的来源与影响。

## 已完成事项 / Completed Work

- 检查 template create route、usage limiter、Chakra client、Vercel production env 与 runtime logs。
- 只读查询 Supabase `api_usage_logs`，确认报错由 Alive 本地 10/hour limiter 产生，不是 Meta 的 WABA template 总量上限。
- 确认首轮 10 次请求包含 9 次上游 validation failure 与 1 次 accepted；后续 blocked retries 也被当前 limiter 计数并延长 rolling window。
- 检查 `healing_schedule_ready` 系列：`v2` 至 `v7` 均成功送达 Meta template-create endpoint，但 Meta 立即返回 `REJECTED`；所有版本重复使用相同 body，改名或切换 category 未改变内容。
- 确认当前 API 只保存/返回 template `status`，未保存或暴露 Meta 的 detailed rejection reason。
- 在 Meta Business Support Home 确认 `healing_schedule_ready_v2` 至 `v7` 的 rejection reason 均为 `Category mismatch`；Meta 将内容识别为包含 `Authentication` content。
- 将 template-create rolling hourly limit 的默认值与示例配置由 10 调整为 100。
- 修正 template-create limiter：通过 Supabase RPC 在转发前原子保留 `attempted` slot，并按 API key serialise concurrent reservations；`blocked` retries 与本地 configuration failure 不再消耗或延长 quota。
- Production Supabase 已应用 `reserve_template_create_slot` migration；function 只授权 `service_role` 执行。
- 在 Vercel Production 新增 `TEMPLATE_CREATE_RATE_LIMIT_PER_HOUR=100`。
- 部署 production deployment `dpl_HDKSCUQ7AY5rTvixbAWpdddfuyMA`，并通过 `/health` 验证。

## 技术决定 / Technical Decisions

- 本轮仅诊断，不修改 Template API、production env 或 usage records。
- 本阶段让 create limiter 只统计实际转发至 Chakra/Meta 的 attempts；`retry_after_seconds` 暂时维持现有 API behavior，不在本次修改 contract。
- Template create limit 保持 rolling one-hour window；immutable `attempted` reservation 负责 quota accounting，`accepted` / `failed` / `blocked` outcome records 继续用于 troubleshooting，不参与 quota query。
- 不修改 `POST /templates` request/response contract；Meta category review 与 Alive API rate limiting 保持独立。

## 风险与阻塞 / Risks and Blockers

- Production 未设置 `TEMPLATE_CREATE_RATE_LIMIT_PER_HOUR`，因此使用默认 10/hour。
- 当前 limiter 统计 `failed` 与 `blocked` 状态；持续重试会继续延长 cooldown。
- 多个旧 template name 被重新创建，Meta 返回 duplicate language content 或 category mismatch。
- Alive records 仍未保存 Meta detailed rejection reason；本次原因由 Meta Business Support Home 人工确认，后续自动诊断仍需上游字段或 webhook 支持。
- Alive limit 提高到 100 后，若短时间内用满 quota，Meta/Chakra 仍可能按其自身 rolling window 返回 upstream rate-limit error。
